# NDS v1.12.0 — قرار الدمج والتنفيذ

**الحالة:** نُفّذ دمج محدود ومثبت المصدر بتاريخ 2026-10-15. هذا هو سجل التكامل الفعلي، لا خطة مستقبلية.

## القرار ونطاقه

اعتمدنا الخيار **D بصيغة ضيقة قابلة للصيانة**: نستخدم من NDS Vanilla v1.12.0 قيم المسافات وأنصاف الأقطار فقط، مع إعادة تصميم محلية لطبقة العرض. لا نعتمد CSS المكونات، أو reset، أو الألوان/الثيم الحكومي، أو الخطوط، أو JavaScript، أو قوالب NDS. تبقى هوية الموقع ومحتواه وبنيته التقنية له.

## التحقق من الإصدار والمصدر

- المستودع: [`mazin-musleh/NDS-vanilla`](https://github.com/mazin-musleh/NDS-vanilla).
- الإصدار المستخدم: tag ثابت `v1.12.0`، وليس `main` أو فرعًا عائمًا.
- الالتزام المثبّت لملف المصدر: `030d1c7ff4ab5a3092c17b93429b1ac55291ea4d`.
- ملف المصدر: [`_sass/tokens/_primitives.scss` في v1.12.0](https://github.com/mazin-musleh/NDS-vanilla/blob/v1.12.0/_sass/tokens/_primitives.scss).
- قرار الإصدار: لم تُنقل أي دلالة من تغييرات `main` إلى إصدار مستقر، ولم يُستخدم الفرع المتحرك بدلًا من tag.

النسخة المحلية `assets/css/nds-1.12-primitives.css` هي مقتطف CSS صغير، يعرّف متغيرات `:root` وحدها. يتضمن رأس الملف رابط المصدر والالتزام والترخيص. إشعار MIT محفوظ في `assets/licenses/NDS-vanilla-MIT.txt`.

## ما نُقل وما بقي محليًا

| المجال | القرار |
|---|---|
| المسافات | اعتماد سلم NDS من `--spacing-none` إلى `--spacing-11xl` كما هو في الإصدار المثبت |
| أنصاف الأقطار | اعتماد `--radius-none`, `--radius-xs` إلى `--radius-xl`, و`--radius-full` |
| لوحة الألوان وهوية الموقع | محلية بالكامل في `styles.css`؛ لم تُستورد لوحة DGA ولا شعارات أو عبارات حكومية |
| الخطوط | الأصول القائمة محليًا (IBM Plex Sans Arabic وNoto Naskh وSatoshi) بلا استيراد خطوط NDS |
| المكونات وreset | لم تُنقل؛ header/hero/timeline/cards/contact/footer محلية |
| JavaScript | لم يُضف أي NDS JS أو اعتماد جديد؛ بقي `assets/js/main.js` تحسينًا تدريجيًا للموقع |
| التصميم الثنائي اللغة | بقيت الصفحتان ومحتوى `content/content.json` ومسارا `/` و`/en/` كما هي |

تفصيل القيم وقواعد الترقية في [`DESIGN-TOKENS.md`](DESIGN-TOKENS.md).

## مواضع الربط

- يضيف `tools/build.py` ورقة primitives قبل ورقة المشروع في `<head>` لصفحتي العربية والإنجليزية.
- صفحة `404.html` المولّدة تحمل الرابطين بالترتيب نفسه لأن قواعدها تستخدم توكنات نصف القطر والمسافة أيضًا.
- ينسخ `tools/package.py` الملف تلقائيًا مع مجلد `assets/`؛ لا يوجد compile step ولا Node runtime.
- روابط الأصول نسبية إلى الجذر ومحلية؛ لم تتغير `_headers` أو CSP. تبقى `style-src 'self'` و`script-src 'self'` من دون `unsafe-inline`.
- ملف primitives لا يحتوي إلا تعريفات متغيرات؛ اختبارات البناء تتحقق من أن المتغيرات التي يستهلكها CSS معرّفة، ومن وجود الملف داخل الحزمة.

## لماذا D لهذا الموقع؟

الموقع صفحة تعريفية عربية/إنجليزية ثابتة، يعتمد على قراءة السيرة، يحمل صورة وPDF، ولا يحتاج نماذج أو تفاعلات تطبيقية. لذلك:

- **A — إعادة تصميم محلية من دون توكنات NDS:** بديل صالح وبسيط، لكنه يترك مقياس المسافة والانحناء محليًا بالكامل ويكرر primitive system صغيرًا.
- **B — نقل مكونات منتقاة:** غير مختار؛ يمزج قواعد ومكونات NDS مع CSS قائم، ويزيد عبء التوافق/الترخيص/الاختبار دون حاجة وظيفية إلى تلك المكونات.
- **C — اعتماد NDS كاملًا وإعادة بناء الواجهة عليه:** غير مختار؛ أكبر نطاق تغيير، ومنظومة مكونات وJavaScript لا يحتاجها الموقع. كما يلزم إعادة تدقيق CSP، وRTL/LTR، وعدم الاعتماد على JavaScript، والهوية والمحتوى بدل افتراض التوافق.
- **D — primitives فقط + واجهة محلية:** يحقق ضبطًا مرجعيًا محدودًا للمسافات والأشكال مع إبقاء الواجهة والهوية والسلوك والتحميل كما صُممت للمشروع. هذا هو التغيير الأدنى الذي يحقق الفائدة المطلوبة.

هذه المفاضلة ليست ادعاءً بأن نقلًا أوسع مستحيل؛ إنما هو اختيار متناسب مع نطاق الموقع ومقيد بصون بنية النشر. القياس الحالي للأصول والتغييرات مسجل في [`IMPLEMENTATION-REPORT.md`](IMPLEMENTATION-REPORT.md)، لا في قياسات قديمة لفرع NDS مختلف.

## التحقق وإعادة البناء

```bash
python3 tools/build.py
python3 tools/package.py
python3 tests/run_static_checks.py
```

اختبار المتصفح المنفصل:

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory dist
python3 tests/run_checks.py http://127.0.0.1:8000
```

يتطلب الاختبار الثاني Playwright وaxe-core وChromium. لا يُعد نجاح الاختبار الساكن بديلًا عن معاينة المتصفح أو اختبار الوصولية؛ الحالة الحالية موثقة في `IMPLEMENTATION-REPORT.md`.

## شروط أي تحديث مستقبلي

1. ثبّت tag والتزامًا كاملًا، وتحقق من محتوى المصدر والترخيص قبل تغيير الملف المحلي.
2. لا تستبدل إصدارًا ثابتًا بفرع `main`، ولا توسع النطاق إلى المكونات/JavaScript بقرار ضمني.
3. حدّث التعليقات في CSS، و`DESIGN-TOKENS.md`، واختبارات الحزمة وروابط HTML وصفحة 404 معًا.
4. أعد build/package والاختبارات؛ افحص فعليًا المسارات العربية والإنجليزية و404 وCSP قبل أي نشر.
