# تدقيق الحالة الحالية ومقارنة NDS الشاملة

**تاريخ الفحص:** 2026-10-22 (Asia/Riyadh)  |  **الفرع:** `arena/eece0d14-al-qaeed`  |  **النطاق:** تدقيق قراءة فقط؛ لا تعديل لتطبيق الموقع، لا نشر، لا commit/push.

## 1. الملخص التنفيذي

الموقع ليس مشروعًا مستقلًا «قبل NDS»: الصفحات الحالية تستخدم بالفعل ملفات NDS vanilla موروثة (ترويسات CSS/JS تحمل `1.12.x-dev`) مع طبقة هوية وتخصيص محلية. لذلك المقارنة الصحيحة هي بين تكامل محلي مخصص ونسخة NDS التطويرية المنشورة في المستودع، لا بين موقع بلا NDS ونظام جديد. بنية الموقع صفحتان ثابتتان (عربية RTL وإنجليزية LTR) و404، يبنيها Python ويجمعها في `dist/` للنشر الثابت.

حالة Git عند بدء الفحص كانت نظيفة على الفرع المحدد. البناء والتغليف والفحوص الساكنة (68/68) واختبارات Python (15/15) وفحص صياغة JavaScript نجحت. لم يكتمل فحص الخطوط: `tools/check_fonts.py` توقف لغياب `fontTools`، ولذلك لم يصل التنفيذ المتسلسل إلى `npm run validate`. لم تُشغّل اختبارات المتصفح في هذه الجولة. لا يُستنتج من ذلك خلو المشروع من جميع العيوب.

## 2. طريقة الجرد ومعيار التصنيف

اعتمدت على الاستدعاء الفعلي في `index.html`, `en/index.html`, `404.html` وعلى ملفات CSS/JS التي تشير إليها الصفحات، لا على أسماء CSS وحدها. جرد NDS أدناه هو صفحات مكونات `components/*.md` الموجودة في checkout upstream عند SHA المذكور (مع استثناء صفحة الفهرس `index.md`). التصنيف A–E يصف العلاقة الوظيفية مع الصفحة الحالية: A مطابق/قريب جدًا، B مكوّن NDS مستخدم مع تخصيص، C وظيفة مشابهة بتنفيذ محلي مختلف، D لا يوجد استخدام وظيفي، E دليل غير كافٍ. وجود bundle مشترك لا يعني استخدام كل مكون بداخله.

## 5. نسخة ومصدر NDS

- تم فحص upstream repository فعليًا عبر shallow clone عند commit `aa49f6d270c5ddaa48770ebd3fcb0a2036ccfc59` (`main` checkout في لحظة الفحص؛ بلا tag يحدد الإصدار لهذه النسخة). `git describe --tags --always` أعطى SHA المختصر دون tag.
- `_config.yml` في ذلك المصدر يعلن `version: 1.12.x-dev` و`latest_release: 1.12.0`؛ إذن هذه نسخة تطوير وليست نسخة إصدار مستقرة محددة. `CHANGELOG.md` يتضمن Unreleased ويعرّف آخر tag سابقًا `v1.12.0`.
- الأصول المحلية أيضًا تحمل banner `1.12.x-dev`، لكن manifest المشروع يقول صراحة إن upstream commit للبناء الموروث غير معروف (`null`). لذلك لا أساوي SHA الحالي upstream بالنسخة المحلية. المقارنة المرجعية للمكونات/الوثائق هي checkout SHA أعلاه؛ مقارنة التطابق byte-for-byte مع مصدر بناء NDS المحلي **غير ممكنة** دون provenance.
- قائمة docs الرسمية للمكونات: `components/`، وصفحة التجميع `components/index.md`، وفهرس بنية العمل `NDS-INDEX.md`، والبيانات `_data/catalog.yml`. مصادر الأنماط `_sass/components/*.scss`, `_sass/layout/*.scss`, `_sass/tokens/*`; runtime `_js/` و`assets/js/`.
- NDS يضم docs ومصدر Sass وJS وحدات/loader وCSS مجمع. أغلب المكونات CSS-only لا تحتاج init؛ التفاعلية تعتمد JS bundle/initializer ذي namespace، delegation أو lazy loading، وبيانات/ARIA متوافقة مع كل component. راجع وثيقة كل مكون (Markup, Variants, Behavior, Built-in Features, API, Related) وملف JS/Sass الموافق. لا يعني وجود كل وحدات source ضرورة تحميلها كلها.
- RTL/LTR تُضبط عبر `dir`, الخصائص المنطقية والمحددات في CSS/JS؛ تتوفر خصائص وصول (ARIA/keyboard/focus) لكن README يصرح اختبارًا يدويًا WCAG 2.1 AA وأن تدقيق axe/قارئات الشاشة planned/known gaps، فلا تُعامل كضمان شامل.
- دمج Cloudflare Pages ممكن كأصول static محلية (لا يتطلب خادم NDS). التكلفة الأساسية اختيار CSS/JS ووحدات الخط/الأيقونات، متطلبات loader، ضبط CSP hashes و`font-src`, توافق inline style/Sass output، المحافظة على JS-free content fallback واختبار الحزمة المنشورة.

### التفسير التفصيلي لمجموعة D (كل الصفوف D في الجدول أعلاه)

لكل عنصر D: الوظيفة هي ما يحدده وصف NDS الرسمي في نفس صف الجرد؛ الوضع: لا يقابله استخدام فعلي في الصفحات الثلاث التي فُحصت. الاحتياج الحالي: غير ضروري لموقع سيرة ثابتة لا يحتوي نموذجًا/بحثًا/بيانات متغيرة/عمليات خدمة. الحاجة المستقبلية تظل مشروطة بإضافة تلك الحالة (مثل forms عند إنشاء طلب، chart عند نشر بيانات كمية، pagination عند قائمة طويلة، إلخ). قيمة الدمج المحتملة هي التفاعل المتخصص/سلوك الوصول الجاهز، لكن الكلفة عادة متوسطة إلى مرتفعة لمكونات JS بسبب wiring/ARIA/CSP واختبار المتصفح؛ لبعض عناصر CSS البسيطة منخفضة/متوسطة. التوصية: تجاهل الاستخدام حاليًا، ودراسة لاحقًا عند وجود حالة فعلية. الثقة عالية في «غير مستخدم على الصفحات الحالية»، ومتوسطة في تقدير الحاجة المستقبلية. لا يوصى باستيرادها استباقيًا.

لإنشاء قائمة مستقلة قابلة للمراجعة دون تكرار جدول آخر: كل صف موسوم D أعلاه هو سجل غير مستخدم ويتضمن الاسم والوظيفة والدليل/الحالة والتوصية. تقدير تكلفة الدمج: منخفضة عادة لـCSS-only؛ متوسطة لـinteractive JS بسيط؛ مرتفعة عند مكونات مع حقول/تحقق/توطين/أصول إضافية مثل محرر، تاريخ/وقت، رفع ملفات، جداول. هذا تقدير تخطيطي لا قياس تنفيذ.

### ملخص مخصص للمكونات ذات المقابل الواضح

- **Main Navigation:** موثق ضمن رف `ui-shell` في NDS، وليس ضمن صفحات `components/*.md` التي جرى عدّها؛ markup NDS حقيقي مع ترجمة/لغة وروابط ذات محتوى شخصي. variants مثل بحث/تنبيهات/مستخدم/أعمدة غير مستخدمة. no-JS navigation fallback ليس مكوّن mainnav ثانيًا وظيفيًا بل مسار ضمان قراءة.
- **Button/Link:** عناصر NDS على markup، لكن أحجام وألوان الهوية وتكبير hit-area للمساعدة/التواصل تخصيص. خصائص NDS الأخرى (groups/progress/icon-only/disabled variants) غير مستخدمة ما لم تظهر بالصفحة.
- **Cards/Definition List/Stepper/Alert:** مكونات NDS مستخدمة للمحتوى؛ لا مساواة بين stepper ومسيرة زمنية دلالية دون مراجعة HTML/قارئ شاشة. بيانات البطاقة/النصوص ثابتة من JSON.
- **Hero/Avatar:** NDS primitive مرئي مع إعادة تشكيل تخطيطية/لونية واسعة؛ هذه حالة B، وليست تطابقًا بصريًا كاملًا. إطار الصورة/portrait محلي.
- **TOC/Share/Tooltip:** وجود markup مثبت؛ تفاعلات scrollspy/share/tooltip لم تختبر في هذه الجولة الحالية. الخصائص غير المستخدمة تحدد بدقة بعد تشغيل browser من build المعاد.
- **Footer/Featured/Feedback/Tags/Divider/Scroll More/Meta:** class markup موجود؛ يجب قراءة السياق للتفريق بين مكوّن مستقل وزخرفة فرعية. حالات الاستخدام والvariants الأخرى ليست دليلًا على طلب الموقع لها.

## 9. المشكلات والمخاطر منفصلة عن قرارات التصميم
